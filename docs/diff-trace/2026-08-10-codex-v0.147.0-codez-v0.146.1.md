## 主要新增功能与修复

### 1. Agent Plugins 与技能发现

- 支持 portable Agent Plugins 安装，在本地、个人、workspace 和 remote plugin catalog 中搜索插件。
- 插件 eligibility、安装时间、MCP config parsing、runtime boundaries、tool namespace collision 和 skills extension 进一步集中管理。
- 关键 PR：[#36544](https://github.com/openai/codex/pull/36544)、[#36409](https://github.com/openai/codex/pull/36409)、[#36919](https://github.com/openai/codex/pull/36919)、[#36796](https://github.com/openai/codex/pull/36796)。

### 2. Thread sections 与长历史浏览

- 会话支持持久化、手动排序的 sections，并在 TUI 中增量浏览长 transcript。
- paginated thread history 增加状态数据库门控、resume 元数据保留、SQLite projection、TUI 分页加载、single-writer ownership 和旧 rollout migration。
- fork、session picker、thread metadata、side conversation、remote compaction 和 goal mutation 继续修复，减少历史加载与恢复时的状态丢失。
- 关键 PR：[ #35722 ](https://github.com/openai/codex/pull/35722)、[ #36007 ](https://github.com/openai/codex/pull/36007)、[ #36948 ](https://github.com/openai/codex/pull/36948)、[ #36950 ](https://github.com/openai/codex/pull/36950)。

### 3. 自动审查与权限控制

- CLI 新增 `--approve-for-me`，支持自动审查审批；Guardian review 使用当前 session/turn 配置并增加 strict MCP elicitation review。
- 权限 profile、sandbox execution、network approval、tool approval handling 和 managed authentication restrictions 更集中地从当前环境配置读取。
- 不熟悉的本地项目需要显式信任；allow amendment 失败时拒绝网络；插件 isolation 和 tool exposure policy 进一步收紧。
- 关键 PR：[ #36373 ](https://github.com/openai/codex/pull/36373)、[ #36960 ](https://github.com/openai/codex/pull/36960)、[ #37132 ](https://github.com/openai/codex/pull/37132)、[ #37027 ](https://github.com/openai/codex/pull/37027)。

### 4. MCP 2026-07-28 与统一网络客户端

- MCP SDK 升级到 3.0.0，加入 2026-07-28 discovery、分页发现、多轮请求、non-blocking startup、concurrent catalog resolution、namespace 限制和 tool catalog 上限。
- MCP OAuth、file upload、TUI network checks、announcement tips、Ollama、codex-protocol 和 remote exec 继续迁移到共享 route-aware HTTP client。
- MCP credentials 按 environment 隔离；hosted credentials、MCP startup readiness、optional server startup 和 tool calls 按 thread 绑定。
- 关键 PR：[ #35724 ](https://github.com/openai/codex/pull/35724)、[ #35725 ](https://github.com/openai/codex/pull/35725)、[ #36001 ](https://github.com/openai/codex/pull/36001)、[ #36310 ](https://github.com/openai/codex/pull/36310)。

### 5. Bedrock、Code Mode 与外部会话

- Amazon Bedrock 支持 cached web search 和 remote conversation compaction；MCP/HTTP/Realtime 的 provider routing 继续统一。
- Code Mode 使用 standalone host、sandboxed V8、双 WebSocket transport、session execution limits 和更明确的 disabled fallback。
- Cursor-managed skills 可导入 Codex，Claude/Cursor imported sessions 的变更可同步且避免重复；external agent history、connector candidates 和 session sources 更完整。
- 关键 PR：[ #36938 ](https://github.com/openai/codex/pull/36938)、[ #36981 ](https://github.com/openai/codex/pull/36981)、[ #36361 ](https://github.com/openai/codex/pull/36361)、[ #36356 ](https://github.com/openai/codex/pull/36356)。

### 6. 安全、TUI、Windows 与发布修复

- command execution items、replayed history 和 bearer tokens 的 secrets redaction 更完整；Windows 非 TTY 进程中断、namespace path、sandbox proxy 和 shell justifications 得到修复。
- TUI 修复 terminal focus 输入丢失、Ghostty keyboard shortcuts、日文半宽字符、emoji、超出 viewport 的 cursor、hyperlink cell width 和 reasoning summary 展示。
- 移除 `codex exec --full-auto`，改用 `--sandbox workspace-write`；Linux 不再发布冗余 bundle archive；macOS notarization 改用 Azure Key Vault。
- 依赖升级包括 Ratatui 0.30.2、MCP SDK 3.0.0 和 V8 150.4.0。

### 7. Codez r1 能力保留

- Codez r1 继续保留 `codez` 命令、branding、独立 state directory、update endpoint、安装布局、在线安装和三平台 offline bundle。
- `--api-base-url`、`--api-key`、`--model`、`--bundle` 离线 API bootstrap 接口继续保留，现有配置、认证和会话数据不要求迁移。
- 本轮主要风险是将 r1 定制与上游新增 sections、plugin search、MCP protocol、approval policy、thread history 和 TUI behavior 对齐。

## 破坏性变化、兼容性风险与迁移注意事项

1. **Agent Plugins 与 catalog 来源（高）**：portable/local/personal/workspace/remote catalog、MCP config parsing 和 runtime boundary 改变插件来源与信任边界。Codez 的离线 marketplace、缓存和 branding 策略必须明确降级行为。
2. **App Server schema（高）**：新增 sections、plugin search、Apps、environment、external-agent、raw response 和 approval 类型会影响严格反序列化。必须重新生成 bindings 并覆盖 unknown fields、union/enum 和通知顺序。
3. **Thread history 与 sections（高）**：分页、SQLite projection、single-writer、manual ordering、fork/resume 和 legacy rollout migration 改变持久化语义。升级前必须使用真实 r1 数据验证恢复与失败回滚。
4. **MCP 3.0 与 OAuth（高）**：多轮 discovery、分页、non-blocking startup、environment credential isolation 和 catalog limit 可能暴露 stale tools、重复连接或 auth scope 错配。
5. **自动审查与权限（高）**：`--approve-for-me`、strict elicitation review、current-turn permission、managed auth 和 network denial 改变审批默认值。Codez 不能仅保留旧 TUI 文案而跳过新的权限判定。
6. **HTTP/代理/网络策略（高）**：OAuth、file upload、Ollama、TUI checks、remote exec 和 announcement requests 迁移到共享 client 后，私有 endpoint、CA、redirect、proxy 和 network approval 必须统一验证。
7. **移除 `--full-auto`（中高）**：脚本、文档、CI 和用户工作流若仍传入旧 flag 会失败，需要迁移到 `--sandbox workspace-write` 并确认审批语义。
8. **Windows/macOS 发布（中高）**：非 TTY 进程终止、namespace paths、sandbox proxy、MSVC Bazel tests、Azure Key Vault notarization 和 Linux archive 变化需要真实平台验证。
9. **Codez 离线安装（中高）**：r1 Release notes 虽声明接口兼容，仍需验证离线 bundle、API key 存储、state directory、update endpoint 和安装失败恢复。

## 结论

`rust-v0.147.0` 相对 Codez 当前上游基线 `rust-v0.146.1` 带来 Agent Plugins、thread sections、自动审查、Cursor/Claude session import、MCP 3.0/2026-07-28、Bedrock compaction、secret redaction 和 `--full-auto` 移除。Codez r1 的 branding、独立状态、在线/离线安装和离线 API bootstrap 需要在这组协议、线程、MCP、审批和 TUI 变化上重新验证。建议把 bindings、真实 session 数据、权限策略、MCP/OAuth、网络策略和跨平台发布设为 P0 发布门槛。
