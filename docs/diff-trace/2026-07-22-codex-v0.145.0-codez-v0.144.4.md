## 主要新增功能与修复

### 1. 分页线程历史、恢复与记忆

- 新增分页线程历史存储、SQLite 投影与断点恢复，支持高效的线程恢复、搜索、持久化名称、子代理历史和 memories。
- 新增历史 occurrence search、legacy view 兼容、rollout lineage 解析以及压缩 rollout 的 doctor 检查。
- 相关提交：`da61f7d8e`（#33364）、`c1862b8db`（#33907）、`5a208c1fc`（#34229）、`2793c826e`（#34386）。

### 2. 外部代理配置导入扩展

- `/import` 扩展到 Cursor 和 Claude Code，覆盖设置、MCP servers、plugins、sessions、commands、connector candidates 和项目级 memories。
- 新增独立的 `external-agent-migration` 实现与大量 TUI/App Server 协议类型。
- 相关提交：`1c4af9639`（#33426）、#31672、#33411、#33444。

### 3. Amazon Bedrock 与模型配置

- 新增受管 Bedrock 登录、登出凭据处理、自定义 endpoint/transport/auth command，并将 GPT-5.6 Sol 设为 Bedrock 默认模型。
- 模型元数据与 OpenAI Docs skill 更新到 GPT-5.6 系列；旧 GPT-5.4 内部选择迁移到 GPT-5.6 Terra/Luna。
- 相关提交：#31327、#33170、#33175、#32288、#33695、#33173。

### 4. 音频与 Realtime V3

- 协议层新增音频输入、音频工具输出和本地常见音频格式处理；Realtime V3 支持流式对话与 handoff 输出。
- 相关提交：`15d7d2a73`（#33929）、`23899f7cb`（#33932）、`b03545b5b`（#33856）、#33261、#34080、#34385。

### 5. Multi-agent V2 稳定化

- Multi-agent V2 标记为稳定，支持子代理默认模型、推理等级、并发限制、角色恢复和更可靠的 agent picker/navigation。
- 配置集中到 `[agents]`：新增 `enabled`、`default_subagent_model`、`default_subagent_reasoning_effort`；`max_threads` 的规范名称改为 `max_concurrent_threads_per_session`，旧名称仍有 alias；`job_max_runtime_seconds` 保留为无操作兼容字段。
- 相关提交：`03bb3b123`（#33550）、#33631、#33657、#33841、#34383。

### 6. TUI 性能与可视化

- 流式 Markdown 改为增量渲染，减少 redraw、clone 和长会话布局成本；命令输出历史改为有界保存。
- 新增安全、可点击的 inline visualization 链接，并在流式渲染和 transcript overlay 中保持上下文。
- 相关提交：`537e69ab6`（#34045）、#34049、#34216、#34223、#34359、`f896ab9f2`（#33925）、#34217、#34346。

### 7. MCP、沙箱与审批可靠性

- MCP client 增加启动超时，OAuth discovery 不再阻塞线程启动；凭据 refresh 串行化，tool catalog 可安全复用且 server 可选择退出缓存。
- Windows exec-server 新增原生沙箱支持，强化 network proxy 路由与 managed permission profile；修复 Windows hook 命令引号。
- 危险命令检测、full-access 二次确认和审批拒绝原因传递进一步强化。
- 相关提交：#32781、#32825、#32229、#33184、#33297、`35c2278dd`（#34423）、#32857、#33926、#32989、#33464、#34400。

### 8. 安装、Code mode 与工具链修复

- 修复 compact release metadata 解析和 macOS code-mode 安装；外部 code-mode host 不可用时可回退到进程内 V8。
- Code-mode image output 要求使用 data URL；exec yield 增加 grace period 与 buffered yield。
- 打包的 ripgrep 更新至 15.2.0。
- 相关提交：#31667、#31876、#31899、#33659、#33867、#34441、#34384。

## 关键文件与子系统变化

按变化文件数，热点主要是：

- `codex-rs/tui/src/`：276 个文件。涉及增量 Markdown、inline visualization、agent picker、审批 UI、导入流程和历史渲染。
- `codex-rs/core/src/`：233 个文件。涉及 session 状态、MCP runtime、工具分发、审批、安全、memories 和 realtime。
- `codex-rs/app-server-protocol/schema/`：118 个文件。新增/修改线程分页、App/connector、音频、Realtime、raw response、scheduled task、环境连接等 JSON/TypeScript schema。
- `codex-rs/external-agent-migration/src/`：54 个文件；`codex-rs/app-server/src/`：50 个文件；`codex-rs/app-server/tests/`：48 个文件。
- `codex-rs/thread-store/src/`、`codex-rs/state/src/`、`codex-rs/rollout/src/`：分页线程历史、SQLite 存储与 rollout 投影的核心实现。
- `codex-rs/exec-server/src/`、`codex-rs/windows-sandbox-rs/src/`、`codex-rs/network-proxy/src/`：执行边界、Windows sandbox 与代理策略。
- `codex-rs/config/src/config_toml.rs`、`codex-rs/config/src/key_aliases.rs`：agents 配置规范化和 Bedrock provider 校验。
- `sdk/python/src/openai_codex/generated/v2_all.py` 与 App Server 生成 schema：下游 SDK/客户端需要重新生成或同步协议类型。

Codez r8 自身的定制与上述热点明显重叠，尤其包括：

- `codex-rs/app-server*`、`codex-rs/cli*`、`codex-rs/tui*`、`codex-rs/login*`、`codex-rs/model-provider/src/amazon_bedrock/`。
- Codez Release/安装链路：`.github/workflows/codez-release.yml`、`.github/workflows/codez-upstream-sync.yml`、安装上下文和离线包校验。
- 当前工作树另有 CLI offline API bootstrap 与 installer 相关未提交改动；本次检查仅观察状态，未读取为 Release 事实、未修改或清理。

## 破坏性变化、兼容性风险与迁移注意事项

1. **App Server 协议风险（高）**：V2 schema 变化广泛，严格反序列化、穷举 enum/union、手写 TypeScript/Python bindings 可能因新消息类型和字段失败。应使用 0.145.0 schema 重新生成，并对旧客户端做向后兼容测试。
2. **线程存储与恢复风险（高）**：分页历史引入 SQLite 投影、checkpoint、lineage 和 legacy view。Codez 若修改 thread resume、daemon、doctor inventory 或状态数据库恢复逻辑，容易出现历史缺失、重复或无法恢复。
3. **TUI 冲突风险（高）**：Codez 在 TUI 的改动面很大，而上游此次也集中重构 streaming、history、composer、agent navigation 与 visualization，机械合并后的 snapshot 通过不代表交互语义正确。
4. **Agents 配置迁移（中高）**：优先写入 `agents.max_concurrent_threads_per_session`；旧 `max_threads` 当前有 alias，但不应继续作为长期配置。`job_max_runtime_seconds` 已是 no-op。需要明确 Codez 是否启用稳定版 V2 及其默认并发/模型策略。
5. **音频与协议枚举（中高）**：`UserInput`、`ContentItem`、tool output、Realtime 版本等增加音频变体；下游若假设输入只含文本/图片，可能崩溃或丢数据。
6. **安全策略变化（中高）**：危险命令、full-access、审批拒绝原因、network proxy 和 Windows sandbox 行为变化。Codez 不应直接保留旧的 exec policy 行为而绕开新确认路径。
7. **Code mode 输出契约（中）**：生成图片必须是 data URL；外部 host 与进程内 V8 fallback 的安装/打包路径均应在 Codez 离线包中验证。
8. **Bedrock 认证（中）**：自定义 auth command 不能为空，provider 校验和 logout 语义有变化；Codez 的登录文案、错误映射与品牌化逻辑需要重新走通。
9. **导入与插件迁移（中）**：导入流程会迁移更多外部工具资产和 memories。Codez 若使用不同 marketplace/品牌命名，应验证路径、来源标记、权限和重复导入行为。
10. **打包工具变化（低至中）**：ripgrep 15.2.0、release metadata 解析和 macOS code-mode 安装修复可能影响 Codez 的离线安装脚本、校验和与产物清单。

## Codez 跟进建议

### P0 — 升级前必须完成

1. 建立 `rust-v0.144.4 -> rust-v0.145.0` 的独立升级分支或可重复补丁队列，先处理 `app-server-protocol`、`thread-store/state/rollout`、`app-server`，再合并 TUI 与品牌化改动。
2. 重新生成并校验 App Server JSON/TypeScript/Python bindings；增加旧 Codez 客户端对新字段、新通知和新 enum 变体的容错测试。
3. 对分页线程历史执行迁移矩阵：旧 r8 数据库、旧 rollout、压缩 rollout、命名线程、fork/rollback/resume、sub-agent history、memories；验证失败时可诊断且不破坏原数据。
4. 对 Codez 大面积 TUI 定制做人工交互回归，重点覆盖长会话 streaming、inline visualization、composer/history search、agent picker、审批弹窗和 thread resume，而不只更新 snapshots。

### P1 — Release 候选版前完成

1. 明确并记录 `[agents]` 的 Codez 默认值，迁移到 `max_concurrent_threads_per_session`，清理对 `job_max_runtime_seconds` 的依赖。
2. 扩展协议兼容测试以覆盖音频 input/output、Realtime V3、raw response completion、Apps read/installed、environment connection 与 scheduled task 类型。
3. 重跑 MCP 启动超时、OAuth refresh、catalog cache opt-out、threadless MCP 和插件服务路由测试。
4. 在 Windows 验证 exec-server sandbox、network proxy、managed permission profiles 和 hook quoting；在 macOS 验证 code-mode 外部 host 与 in-process V8 fallback。
5. 将 Codez 的 login、Bedrock error、marketplace/plugin、daemon managed install 和 update loop 定制逐项重放，避免品牌化补丁覆盖上游新语义。

### P2 — 发布与运维完善

1. 更新离线安装包的二进制清单、校验和、ripgrep 版本和 release metadata 测试；覆盖 macOS/Linux 各架构。
2. 在 Codez Release notes 中补充具体变更摘要，不仅保留 Full Changelog 链接，以便后续自动追踪准确区分 fork 修订内容。
3. 为 0.145.x 升级增加可观测性：线程投影失败、MCP 超时、sandbox/proxy 拒绝、import 失败类别和 realtime/audio 协议错误。

## 结论

`rust-v0.145.0` 相对 Codez 当前对应基线 `rust-v0.144.4` 不是小型补丁，而是跨线程存储、App Server 协议、TUI、multi-agent、MCP、音频/realtime 与安全执行边界的大规模升级。Codez r8 的定制面与上游高变更区域高度重叠，建议按 P0 顺序拆分升级，并把协议生成、历史迁移和 TUI 人工回归作为发布门槛。
