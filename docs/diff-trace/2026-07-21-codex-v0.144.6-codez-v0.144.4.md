## 主要新增功能与修复

### `rust-v0.144.5`：危险命令检测与拒绝原因

- 扩大强制删除命令的识别范围：除 `rm -f`、`rm -rf` 外，还覆盖 `rm -fr`、分离参数 `rm -r -f`、`--force`、绝对路径 `/bin/rm`，以及 `sudo`、`env` 包装形式。
- 能从复杂 shell 语法中提取字面命令，包括管道、条件分支、循环、命令替换、嵌套 `bash -c` 和 `trap`，用于识别内部的强制 `rm`。
- 为危险命令返回结构化匹配结果，并在拒绝时给出更明确的信息：`rm -f style commands are not permitted. Use a safer approach`。
- 当审批策略为 `AskForApproval::Never` 时，检测到危险命令会直接禁止；不再因 sandbox 显式关闭而放行。

### `rust-v0.144.6`：GPT-5.6 模型元数据热修复

- 刷新 GPT-5.6 Sol、Terra、Luna 的内置 instructions。
- 将上述模型的 `context_window` 与 `max_context_window` 从 372,000 修正为 272,000 tokens。
- 该版本是针对 0.144 分支的窄范围热修复，未引入其他代码子系统变化。

### Codez `r8` 修订

- 修复离线安装包版本校验：Release/二进制版本继续包含 `-rN`，而 `codex-package.json` 的版本按对应上游版本 `X.Y.Z` 校验。
- 更新中英文 README 中的离线包示例至 `r8`。
- `r7...r8` 共修改 4 个文件，13 行新增、10 行删除；不改变 Codez 对应的上游基线 `rust-v0.144.4`。

## 破坏性变化、兼容性风险与迁移注意事项

- **危险命令行为变化（高）**：`approval_policy = never` 下的强制删除命令将由部分场景可执行变为直接拒绝。依赖 `rm -f`/`rm -rf` 的自动化、安装、清理和测试脚本可能需要改用显式文件操作、非强制删除或其他更安全流程。
- **检测范围扩大（高）**：即使强制删除藏在管道、循环、条件、命令替换、`sudo`、`env` 或 `trap` 中，也可能被阻止。Codez 应重点检查离线安装、升级、临时目录与 release 清理路径。
- **上下文窗口修正（中）**：若 Codez UI、请求预算、压缩阈值或测试假设仍按 372k 计算，升级后应统一改为 272k，避免服务端拒绝、过晚压缩或错误的剩余上下文展示。
- **内置 instructions 更新（中）**：模型行为可能因 instructions 文本变化而改变。Codez 的品牌提示、工具约束、中文交互和定制功能需要回归测试，避免上游提示覆盖或弱化 Codez 特性。
- **版本三元关系（中）**：Codez `r8` 已明确区分上游包元数据版本 `0.144.4` 与 Codez Release/二进制版本 `0.144.4-r8`。升级到 0.144.6 时应保留这一规则，并同步 `.codez/upstream-version`、workspace/package 元数据及离线安装测试。
