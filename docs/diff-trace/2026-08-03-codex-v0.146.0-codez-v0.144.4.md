## 主要新增功能与修复

### 1. 线程生命周期与会话管理

- `/new` 和 `/clear` 可为新会话命名，App Server 新增持久化 thread pinning，并允许在线程之间切换时保留 side conversations。
- 分页线程历史从 0.145.0 的存储、搜索、恢复和 memories 基础继续扩展到可分页 fork；同时支持不出现在常规线程列表中的 ephemeral fork。
- 中断、fork、导入和 replay 时更完整地保留用户输入、最终响应、失败错误、时间戳和审批 reviewer。
- 关键提交：`25d2dfcad`（#34605）、`400ee190c`（#34840）、`7d4b417cd`（#35011）、`05f000263`（#35220）、`1811b67a8`（#35251）。

### 2. Agent Plugins、skills 与 marketplace

- 新增 Agent Plugins manifest 支持和 workspace plugin publish 能力；marketplace 增加 Amazon Bedrock API 来源与 Claude Code bundled marketplace 推断。
- executor 提供的 skills 可被发现并通过 skill tools 安全读取资源，显式选择的 executor skill 也可读取关联资源。
- skill catalog 在上下文预算紧张时优先保留条目、逐步丢弃描述，并在必须截断时发出警告。
- 关键提交：`a28374e0d`（#35105）、#35254、`7c7178313`（#35184）、`fe8500c0a`（#35198）、`6278742c4`（#34732）、`2c92af09c`（#34997）。

### 3. 远程 Code Mode 与 WebSocket

- Code Mode host 新增 WebSocket transport，App Server 可连接远程 Code Mode host；同时可通过配置禁用进程内 host fallback。
- exec-server WebSocket、HTTP 和环境注册请求都接入统一代理策略，并补充连接建立 tracing、network policy callback 和兼容性 metadata 边界。
- 关键提交：`0dfa778da`（#35078）、`f61b51ddd`（#35098）、#35056、#35266、#35275。

### 4. MCP 与 Apps 动态刷新

- MCP connection manager 拆分并集中到 `McpRuntime`/`McpConnectionSet`，运行时刷新会复用健康连接、替换已关闭连接。
- session auth、配置和受管 MCP requirements 变化时可刷新 runtime；Apps tools 在刷新后保持最新，无需重启健康连接。
- MCP auth discovery、redirect、remote plugin 和请求均逐步迁移到共享、策略感知的 HTTP client。
- 关键提交：`e19e65317`（#34952）、`f201c30c5`（#35151）、`6c729ef1c`（#35146）、`091e4a5d7`（#35028）、#35239。

### 5. 统一 HTTP、代理与出站安全

- 新增 route-aware HTTP client pool 与 policy-aware builder，认证、插件下载、MCP 授权、remote exec、WebSocket、redirect、LM Studio 和 updater 统一遵守已配置代理。
- system proxy 会在 redirect 时重新解析；managed proxy 环境支持 `CARGO_HTTP_CAINFO`，并加强 sandbox/Guardian 中的代理策略传递。
- network approval 的取消和并发处理被强化，exec-server 可接收 network policy 请求。
- 关键提交：#34447、`841e47b8f`（#34479）、#34630、#34655、#34678、#35023、#35267。

### 6. TUI 响应性与交互修复

- turn interrupt 改为非阻塞；键盘事件适配、窄终端 header、OSC 8 hyperlink、mention 结果刷新和 keymap action menu 均有修复。
- Windows 修复导航键处理；过长源码行跳过语法高亮，降低长会话或大输出下的卡顿风险。
- 0.145.0 已引入的增量 Markdown、bounded command output、inline visualization 和 agent navigation 在本范围内仍是大面积 TUI 重构的一部分。
- 关键提交：`62ba64813`（#35000）、`bbad09a83`（#34625）、#34775、#34778、#35365、#35375。

### 7. Windows 执行、沙箱与审批

- Windows sandboxed process tree 使用 job objects 可靠终止；elevated sandbox、network proxy 和 Guardian session 的代理配置进一步加固。
- 0.144.5 扩大危险 `rm` 形式检测，0.145.0 继续强化 full-access 确认与审批拒绝原因；0.146.0 保持并扩展 network approval 并发安全。
- 关键提交：`9b33613db`（#34624）、#34629、#35036、#33455、#33464、#35267。

### 8. 模型、发布与管理能力

- 0.144.6 刷新 GPT-5.6 Sol/Terra/Luna bundled instructions，并将 context window 修正为 272,000 tokens。
- 0.145.0 新增 Bedrock 登录与自定义 transport、音频 input/output、Realtime V3、稳定版 multi-agent V2，以及 Cursor/Claude Code 配置和 session 导入。
- Release artifacts、channel metadata 和 installer aliases 开始发布到 OpenAI 托管基础设施并保留 GitHub fallback；macOS helper 增加签名和 notarization。
- 新增 ent26 enterprise plan 识别和 in-app update 管理策略。关键提交：#34505、#34729、#35238、`95637f705`（#35537）。

### 9. Codez r9 离线 API 配置与安装回滚

- 新增隐藏的 `offline-api-bootstrap` 子命令，支持通过 `--api-base-url` 和可选 `--model` 配置 OpenAI-compatible API，并从 stdin 保存 API key；拒绝非 HTTP(S)、缺少 host、包含 URL 凭据或空模型输入，并在强制 ChatGPT 登录时禁用该流程。
- 离线安装脚本新增 `--api-base-url`、`--api-key`、`--model`，要求 endpoint 与 key 成对提供；安装前快照 symlink、二进制、`config.toml` 和 `auth.json`，失败时回滚，且避免在 shell xtrace 和子进程命令行中暴露 key。
- 关键提交：[`fafec8a6778b`](https://github.com/streamsc/codez/commit/fafec8a6778bde9c8bcfacde8ee20c7f8f549de3)（support offline API configuration）、[`4f87df0d00fd`](https://github.com/streamsc/codez/commit/4f87df0d00fd5702a349a5b8648d6dca2bdead40)（configure during install）、[`8a3016266aca`](https://github.com/streamsc/codez/commit/8a3016266aca4140bd3a48893c6a3c8e34cd383a)（update offline release examples）。

## 关键文件与子系统变化

按变化文件数量，主要热点为：

- `codex-rs/core`：386 个文件。集中于 session/thread 状态、MCP runtime、world state、审批、skills、realtime、HTTP 与代理策略。
- `codex-rs/tui`：324 个文件。覆盖 composer、thread navigation/fork、streaming、keymap、审批、mention、visualization 和 Windows 输入。
- `codex-rs/app-server-protocol`：170 个文件；`codex-rs/app-server`：156 个文件。V2 JSON/TypeScript schema 增加 Apps read/installed、environment notifications、external-agent import、raw response、thread entry/realtime 等类型。
- `codex-rs/exec-server`：69 个文件；`codex-rs/network-proxy`：26 个文件；`codex-rs/windows-sandbox-rs`：24 个文件。对应远程执行、统一代理、network policy 和进程树终止。
- `codex-rs/external-agent-migration`：55 个文件；`codex-rs/thread-store`：34 个文件；`codex-rs/state`：36 个文件。对应外部工具迁移、分页历史和 SQLite 投影。
- `codex-rs/codex-mcp`：27 个文件；`codex-rs/http-client`：17 个文件；`codex-rs/code-mode` 及 host/transport：远程连接、runtime refresh 和共享 HTTP client 的核心实现。
- `sdk/python/src/openai_codex/generated/v2_all.py` 及生成的 JSON/TypeScript schema 大幅变化，下游 SDK 或手写 bindings 必须同步。

从文件状态看，上游范围新增 438 个、修改 1,504 个、删除 78 个、重命名 13 个文件。单文件热点包括 App Server `turn_start`、`thread_fork`、`thread_resume` 测试，external-agent migration，MCP connection manager，TUI composer/session tests，以及生成协议 schema。这说明风险不只是新增 API，也包含已有线程与连接生命周期语义的重构。

Codez r9 继承的定制主要集中在 `codex-rs/tui`（184 个文件）、`codex-rs/cli`（19 个文件）、安装/发布 scripts、login、app-server daemon 和 exec；本次 r9 额外触及 `codex-rs/cli/src/offline_api_bootstrap.rs`、`codex-rs/cli/src/offline_api_bootstrap_tests.rs`、`codex-rs/core/src/config/edit.rs`、`scripts/install/install-codez-offline.sh` 和 `scripts/install/test_codez_offline.py`，与上游本次高变化区显著重叠。

## 破坏性变化、兼容性风险与迁移注意事项

1. **App Server 协议与生成 bindings（高）**：新增通知、参数、response 和 union/enum 变体会影响严格反序列化与穷举匹配。必须从 0.146.0 schema 重新生成 TypeScript/Python bindings，并保留旧 Codez 客户端容错。
2. **分页线程存储与 fork（高）**：从旧 rollout 到 SQLite projection/checkpoint/lineage，再到 paginated/ephemeral fork，涉及持久化语义变化。升级测试必须使用 r9 的真实旧数据副本，覆盖 resume、search、fork、archive、pin、side conversation 和 sub-agent history。
3. **TUI 合并冲突（高）**：Codez r9 继承 184 个 TUI 定制文件，上游范围有 324 个 TUI 变化文件。snapshot 重新生成不能替代人工验证 composer、thread switch、fork、interrupt、mention、approval 和窄终端布局。
4. **MCP/Apps 生命周期（高）**：运行时刷新、连接复用、auth/config 变更和 tool catalog revision 绑定改变连接所有权。Codez 若保留旧 daemon 或 plugin refresh 补丁，可能出现 stale tools、重复连接或刷新死锁。
5. **代理与网络策略（高）**：多条请求路径迁移到共享 route-aware client。Codez 的离线 API、私有 endpoint、Bedrock、登录和 updater 若绕开 builder，可能失去代理、CA 或审批策略。
6. **Code Mode host 契约（中高）**：新增远程 WebSocket transport 和可禁用 fallback。需明确 Codez 离线发行物是否携带外部 host、何时允许 in-process fallback，以及代理和鉴权失败时的错误行为。
7. **插件 manifest 与 marketplace（中高）**：新 Agent Plugins manifest、workspace publish、remote plugin ID 和 marketplace 推断可能与 Codez 品牌化、离线 marketplace 或插件缓存策略冲突。插件来源和脚本 attribution 不能在移植时丢失。
8. **配置迁移（中高）**：0.145.0 将 multi-agent 设置集中到 `[agents]`，规范并发键为 `max_concurrent_threads_per_session`；旧 alias 和 no-op 字段不应继续写入新配置。0.146.0 又增加可禁用 host/tool 能力和 managed update policy，应避免 Codez 默认值意外覆盖企业策略。
9. **Windows/macOS 打包（中）**：Windows job objects、elevated sandbox、代理和键盘行为需要真实平台回归；macOS helper 签名/notarization 与新 installer source 会影响 Codez 自有发布链路和离线包清单。
10. **模型与多模态（中）**：272k context 元数据、音频 input/output、Realtime V3 和 custom provider standalone web search 会扩展协议输入面。任何只处理文本/图片或硬编码旧模型窗口的 Codez 逻辑都需更新。
11. **离线 API bootstrap 与安装回滚（高）**：r9 会写入 `openai_base_url`、`model_provider`、可选 `model` 和认证凭据；管理员必须确认 URL、模型和 key 的来源、存储后端、强制 ChatGPT 策略及失败回滚行为，并补齐 shell history、进程列表、权限和中断场景测试。

## Codez 跟进建议

### P0 - 升级分支合入前

1. 将升级拆成可重复层次：先同步 protocol/schema 和 generated bindings，再同步 thread-store/state/rollout 与 app-server，随后处理 MCP/HTTP/proxy，最后合并 TUI 和品牌化补丁。
2. 建立 r9 数据迁移矩阵，覆盖旧 rollout/SQLite、命名和固定线程、resume/search、paginated/ephemeral fork、side conversation、sub-agent、memories、archive/delete；失败测试必须证明原数据未被破坏。
3. 重新生成 App Server JSON/TypeScript/Python 类型，运行旧客户端到新服务端、新客户端到旧数据的兼容测试，重点检查新 enum/union、notification 和 raw response。
4. 对 Codez TUI 定制逐块 rebase 并做人工交互回归，重点验证 composer、streaming、interrupt、thread switch/fork、mention、approval、agent picker 和窄窗口。
5. 审计所有出站 HTTP/WebSocket 路径，确保 login、MCP、plugin、remote exec、Code Mode、Bedrock、updater 和 Codez 离线 API 均经过统一代理/CA/审批策略。
6. 为 r9 的 `offline-api-bootstrap` 与离线安装参数增加端到端测试：验证 URL/key 成对校验、stdin 读取、ChatGPT 强制登录拒绝、配置与凭据原子性、安装回滚，以及 key 不进入 xtrace、历史和子进程 argv。

### P1 - Release 候选版前

1. 对 MCP runtime 做 auth/config 热刷新、closed connection replacement、Apps tool refresh、catalog revision、OAuth 和并发刷新压力测试。
2. 验证 Agent Plugins manifest、workspace publish、marketplace 路径、remote plugin ID、trusted script attribution 和离线插件缓存；明确 Codez 不支持能力的降级表现。
3. 在 Windows 验证 job object 进程树终止、elevated sandbox、network proxy、Guardian、导航键和 hook quoting；在 macOS 验证 host/helper 签名、notarization、安装源 fallback 和离线安装。
4. 明确 `[agents]`、remote Code Mode fallback、custom provider web search 和 managed in-app update 的 Codez 默认值与管理员覆盖优先级。
5. 扩展协议测试到音频 input/output、Realtime V3、Apps read/installed、environment notification、external-agent import 和 raw response completion。

### P2 - 发布与运维

1. 更新离线产物清单、校验和、installer channel metadata、macOS helper 签名和 GitHub fallback 测试。
2. 增加 thread projection/fork、MCP refresh、proxy route、remote Code Mode、plugin import/publish 和 update policy 的可观测性与诊断信息。
3. 在 Codez Release notes 中写明每个 `-rN` 的实际功能和修复摘要，避免只提供 Full Changelog 链接，方便后续自动追踪修订差异。

## 结论

`rust-v0.146.0` 相对 Codez 当前上游基线 `rust-v0.144.4` 是连续两个稳定版本加两个 hotfix 的大跨度升级。新增能力集中在线程持久化与 fork、Agent Plugins、远程 Code Mode、MCP/Apps 动态刷新和统一 HTTP/代理策略；与此同时，Codez r9 继续继承上游变化最大的 TUI 定制，并新增离线 API 配置与可回滚安装流程。建议把协议生成、旧线程数据迁移、网络策略一致性、离线凭据安全和 TUI 人工回归设为 P0 发布门槛，避免以一次性大合并方式直接推进。
